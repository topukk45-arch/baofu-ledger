## 解决什么问题

记账 App 的老问题：**手记会漏，导账单又会重复、分类全乱**。一年的微信 + 支付宝账单两千多笔，里面混着退款、转账、红包、零钱提现、信用卡还款；导进来以后最费事的是逐笔分类。

记问的做法：

| 难点 | 记问怎么处理 |
|---|---|
| 账单和手记重复 | 按时间、金额、对方一层一层配对，能确定的自动合并成一条；拿不准的进「待处理」让人定，不猜 |
| 退款、转账乱算 | 退款自动挂回原单、全额退款的一对直接跳过；转账、提现、还款单独一类，不算进收支 |
| 分类太多看不过来 | 规则 → 从你的历史里学 → 内置词表 → 支付宝分类，逐层推荐；剩下拿不准的**按组**交给 AI，一次整理几百笔 |
| 导错了怎么办 | 每次导入、每次 AI 修改都先自动备份，能整批撤销；撤销会算依赖链，后来改过的不动 |
| 隐私 | 不联网、不接任何 AI 接口；复制给 AI 之前自动打码，可以把个人姓名换成「个人A / 个人B」 |

实测：一次导入一年的真实账单，**绝大部分能靠「AI 按组整理」一次分好类**，剩下几笔在「成组确认」里点几下。

## 功能

**记账**
- 一屏记完：记账时间、金额、收支、最近常用的 4 个分类、统计口径、备注、常用模板都在一个面板里；金额用 App 自己的数字键盘（长按连续输入 / 删除），键盘大按钮直接「保存」
- 选了分类自动带出收支（按这个分类以前怎么记的）；分类抽屉里搜不到能一键新建
- 记完底部小条：「补备注」「再记一笔」；改好一笔、删一笔也是小条，删了 5 秒内能撤销
- 长按任何一笔：修改 / 再记一笔 / 删除；退款从原单发起，部分退款、多次退款都算得清
- 三种统计口径：**计入**（算收支）、**不计**（信用卡还款、重复记录）、**往来**（转账、借还钱，只动结余）；能标「期初余额」

**看账**
- 账单页按月 → 周 → 天三层：周是一条带 7 根小柱子的分隔线，天是卡片；没记账的日子标出来、一点补一笔，也能标「这几天没花钱」
- 一周 / 一天是同一个面板，左右滑换周换天，跟手、有动效
- 统计页：日历热力四档 + 周合计、分类占比和「上月同期」比较、总结余算式一键展开、全部记录的分类汇总
- 预算：每个分类设预算，进度条上叠一层「这个月过了多少」的斜纹，一眼看出花得快不快；超预算时账单页顶上提醒；能按过去几个月的中位数给预算建议
- 搜一笔：日期 / 金额 / 收支 / 分类 / 口径 / 备注多选组合，条件一个个是能点掉的标签，最近搜过 10 条；搜到的能批量改分类、口径（能撤销）
- 日子：倒数日、纪念日，置顶的放账单页顶上

**外观**
- **24 个预设主题色**，按红赭、青绿、蓝紫、墨灰四组排，每个都有名字（苏芳、天水碧、秘色、松烟墨……）
- 也能自己调：色相 / 深浅 / 鲜艳三条拖着选，整个 App 实时跟着变；自己调的颜色也会自动起一个中文名（比如「近黄栌」「玄青」），附一句短评
- 不管选什么颜色，按钮字、强调字、小字都自动推到 4.5:1 以上对比度；登录页就能换

**账单导入**（开发开关里，测试中）
- 微信 xlsx、支付宝 CSV、加密压缩包（解压密码当场输、不保存）；也能在文件管理器里「用记问打开」
- 先核对笔数和金额，再按「和手记对不上的 / 退款和转账 / 分类 / 金额」分步看，没事的步骤不出现；也能直接一键导入
- 大额先问一句「这笔算不算收支」；按天对账；只对账（只补漏记的几笔）；拿不准的进待处理以后再定
- 每笔新记录带着账单原文；和账单合并过的手记能拆开；每次导入都能整批撤销、能恢复备份
- 导入记录里记下这次多少笔自动定了、多少要人看、分类是哪一层推荐的、导入后又改了多少（只存数字），用来量推荐准不准
- 月初提醒「上个月的账单可以导了」

**分类整理**
- 待确认分类：逐条确认、按分类成组确认（一组一下）、一键按新规则重新推荐
- AI 按组整理：导出一段文字给你自己用的 AI，回复粘回来勾选确认；也能让 AI 再检查一遍整次导入（标出可能重复、可能漏配的）
- 你改过的会问「以后都这样吗」，存成规则；规则能在「管理导入规则」里改、删

**数据安全**
- 多账号、多存档；导出 / 导入存档文件；连自己的 OneDrive 自动云备份（单号表也能单独存一份）
- 导入、撤销、AI 修改、恢复之前都自动备份，分种类各留几份
- 被系统杀掉后回来：停在哪一页、填到一半的记一笔都还在
- 启动先画上次的首屏快照，看不出加载过程

## 技术亮点

### 1. 无框架的模块化前端，依赖方向由测试锁死

原生 JavaScript（不用 React / Vue），约 2.2 万行业务代码，拆成 25 个模块，分 6 层：

| 层 | 模块 | 管什么 |
|---|---|---|
| 5 外壳 | settings · tabs · login · back · boot | 设置、页签切换、登录、返回键层级、启动 |
| 4 页面 | forms · detail · ledger · search · stats · days · cats | 记一笔、详情、账单、搜一笔、统计、日子、分类管理 |
| 3 业务 | ai-export · import-entry | 导出给 AI、账单导入入口（按需加载导入模块） |
| 2 面板底座 | sheet · keypad · text · ask · date · monthstrip | 底部面板、数字键盘、文字输入、提示框、日期选择、月份浮条 |
| 1 存储 | store | IndexedDB 按月分块、写入队列、备份、撤销 |
| 0 基础 | base · theme | 工具函数、性能记录、主题配色计算 |

- 每个模块一个 IIFE、对外只有一个 `window.JiwenXxx` 入口；**只许调用下层**，往上的调用只有登记过的三种回调口。
- 依赖规则写成测试（语法树扫描 + 真起 App 检查全局变量），新代码越层、漏出全局名字，CI 直接拦下。
- 这套结构是从一个 800 KB 的单文件**分 26 步原样搬出来的**：每一步逐字节对比页面输出、全部测试通过，不改一行逻辑。

### 2. 账单导入：纯函数流水线 + 后台线程

```mermaid
flowchart LR
  F["账单文件"] --> P["parse"] --> R["route"] --> C["classify"] --> M["match"] --> PL["plan"] --> W["write"] --> DB[("IndexedDB")]
```

| 步骤 | 做什么 |
|---|---|
| parse | 认来源、解码、读 xlsx、解加密 zip、核对笔数 |
| route | 用单号表去重、退款配原单、转账 / 提现 / 还款单独处理 |
| classify | 规则 → 从你的历史里学 → 内置词表 → 支付宝分类，逐层推荐 |
| match | 和手记按时间、金额、对方配对，拿不准的进待处理 |
| plan | 汇总成方案，每个文件 × 收支的差额核到 0 分，列出要人定的几件 |
| write | 生成写入清单，主页面一个事务写进 IndexedDB（写之前先备份） |

- 每一步都是**纯函数**（不碰页面、存储、网络），浏览器、Web Worker、Node 测试里用同一份代码；计算在后台线程跑，界面不卡。
- 笔数和金额**对账到分**：每个文件 × 收支的差额拆开解释，合计必须差 0 分，对不上不让往下走。
- 读 xlsx、解 WinZip AES 加密包：SHA-1、HMAC、PBKDF2、AES 都是自己写的 JS，不依赖 WebCrypto 和第三方库（解压用 tiny-inflate）。
- 撤销不是简单回滚：`undo.js` 算出批次之间的**依赖链**（后一次导入合并了这批的记录、AI 改过这批的记录……），从新到旧撤；导入后你亲手改过的字段，按字段级指纹认出来、保留不动。

### 3. 把 AI 当成「用户自己的工具」，而不是接口

记问不调用任何 AI API。导出给 AI 的是一段**协议化的文字**，AI 的回复按协议读回来：

- **按组压缩**：同一商户 / 同一收支归一组，每组带统计特征（平均每笔、单笔范围、日期范围、常见时段、工作日或周末、疑似月固定扣款），几百笔变成几十行，AI 一次看得完、判断有依据。
- **固定回复格式**：第一行抄导出时间戳（防止拿旧回复改新数据），一行一组「G号 | 分类 | 理由」；分类不在白名单、格式不对的行单独列出来，不会乱改。
- **隐私**：手机号、卡号、邮箱打码；可选把个人对方换成稳定的别名，读回时按组号对回原记录。
- **可撤销**：写入走和导入同一套「先备份、一个事务、能撤销」。

### 4. 启动速度：首屏快照

大脚本解析完才能画界面，低端机上要几百毫秒。做法是把用户最后看到的首屏 HTML 存下来，下次启动在脚本跑之前先画出来，原生启动画面等这一帧画好才收；真界面画好后无缝替换。每次启动的各段耗时（含原生层：进程启动 → Activity → WebView → 首屏）记在 App 内的性能记录里，用真机数据而不是猜测来调。

### 5. 主题色：从一个颜色算出整套配色

选一个颜色，`buildPalette()` 算出几十个配色变量：按钮底色、按钮上的字、强调字、页面底、卡片、面板、边框、日历热力四档、预算斜纹……

- 每一种字色都在它可能出现的每一种底色上算对比度，不够 4.5:1 就沿着同一色相往深里推，直到够为止；按钮底和页面底太接近时自动加一圈细边。
- 24 个预设逐个量过；自己调的颜色同样保证。真浏览器检查会把 24 个主题挨个套上、量画出来的每一处字和底色。
- 自己调的颜色在 OKLCH 色彩空间里起中文名：离某个预设很近就叫「近黄栌」，像传统色词典里的某个就用它（`#123456` →「玄青」），都不像就按规则拼（`#ff66aa` →「晴苏芳」：「晴」是偏浅浓郁，「苏芳」来自色相 356°），并说明为什么叫这个名字。
- 再给一句短评，比如「冷调 · 不浓不淡 · 适中 · 按钮配浅字 5.3:1」。
- 老 WebView 不认 `color-mix()`，所有混色都在 JS 里先算好成变量，测试里比对和 `color-mix()` 算法一致。

### 6. 测试：186 组、6200 多条，测试不过不出包

| 层次 | 做法 |
|---|---|
| 整页功能 | jsdom 在 Node 里跑完整 App，模拟点击、键盘、返回键、IndexedDB |
| 逐字节回归 | 新旧两版同样的操作，账单列表、统计、备份文件、AI 导出逐字节比 |
| 导入标准答案 | 固定的虚构账单真导一遍，和存好的结果逐字节比 |
| 性质测试 | 随机组合「记账 / 导入 / 撤销 / 恢复 / AI 修改」，每步查各处数据对得上（CI 每次跑几十步，本地可调到几百步） |
| 规模 | 12 万条记录进账号、记一笔、切统计页的耗时 |
| 真浏览器界面检查 | Playwright + Chromium 按手机尺寸逐页量：点击区 ≥ 48px、按钮被盖住 / 被切半截、字被截断、24 个主题的对比度 |

GitHub Actions：推到 main → 跑全部测试 → 打 APK → 自动发布；测试有一条不过就不出包，失败条目直接标在 Actions 页面上。

## 怎么做出来的

需求、交互设计、真机实测和每一版的验收由作者完成；代码在 AI 编程助手（Claude Code）协作下完成。为了让 AI 写的代码可控，项目把规矩写成了能执行的东西：

- [CLAUDE.md](CLAUDE.md)：每个模块、每条交互规则、每种数据怎么存怎么撤，写成大白话，改代码前先读、改完同步更新；
- 「操作 × 数据表」：哪个操作会改哪份数据，加功能必须更新，性质测试按这张表随机组合检查；
- 测试只增不减、不许放宽；动数据的改动一版只做一件事；每一轮有交接文档 [HANDOFF.md](HANDOFF.md) 和发版说明。

## 跑起来

```bash
# 跑测试
cd tests && npm install && npm test

# 两个版本逐字节对比页面输出
node tests/regress.js 旧版.html www/index.html

# 真浏览器界面检查（要装 Playwright 的 Chromium）
NODE_PATH=$(npm root -g) node tests/ui/audit.js 输出目录 --only main --shots
```

打包：推到 main 后 GitHub Actions 自动出 APK（Actions →「构建安卓 APK」→ Artifacts），也可以在 Actions 页面手动 **Run workflow**。本地不需要装 Android Studio。

目录：`www/index.html` 页面骨架 · `www/app/` 主程序模块 · `www/import/` 账单导入（打开导入时才加载） · `android/` 原生壳 · `tests/` 测试。详见 [tests/README.md](tests/README.md)。
