# 记问 · 自动化测试

用 [jsdom](https://github.com/jsdom/jsdom) 在 Node 里加载完整的 `www/index.html`，像真人一样点按钮、填表单，再检查页面和存档数据。不需要浏览器，也不需要手机。

1015-A 起账单导入的代码单独放在 `www/import/` 下：纯计算部分（`core.js`、`merchants.js`）直接在 Node 里 `require` 进来测，不用 jsdom；要加载整个页面时，jsdom 用 `helpers/import-files.js` 里的资源读取器把外部脚本读进来。1016-L 起新加的导入页测试用 `helpers/app.js` 起 App（开着开发开关、停在设置页，带 `importFiles` 真导一批），不用每个文件抄一遍。

1013-D 起账本存在 IndexedDB，1013-G 起按月分块存。jsdom 没有 IndexedDB，测试用 [fake-indexeddb](https://github.com/dumbmatter/fakeIndexedDB)（纯 JS 实现，只在测试里用，不进 App）。

1017 起：界面检查分支 `ui-review` 已合并进 main（10-17，快进到 2c7d9af），以后改界面、改功能都在 main 上做，测试也只在 main 上跑；界面量尺照旧用 `tests/ui/audit.js`。

**所有测试数据都是虚构的**，不含任何真实账单。

## 运行

```bash
cd tests
npm install          # 首次
npm test             # 跑全部测试，任何一组失败退出码为 1
node j-refund.test.js            # 只跑某一组（默认测 ../www/index.html）
node j-refund.test.js 某个.html   # 测指定文件
```

GitHub Actions 每次打包前都会先跑 `npm test`，不通过就不出包（1020-J 起只有推 main 和手动触发才打包）。

1020-J 起 `npm test` 同时跑几个文件（按核数，最多 4 个；`JOBS=1 npm test` 一个一个跑），每个文件的输出攒齐了整段打印、写用时；真等计时器的（等动画、长按、键盘、停下来存）写在 `run-all.js` 的 `SERIAL` 里（或文件里写一行 `// @serial`），等别的跑完再一个一个跑。本机 4 核约 5 分钟（原来约 11 分钟）。单独跑一个：`node -r ./tools/inline-hook.js xxx.test.js`。

## 导入代码怎么测（1015-A 起）

- 纯计算（`www/import/core.js` 这类）：`const core=require('../www/import/core.js')`，直接调函数断言，不用 jsdom，也不用 `boot`。以后的解析、配对、分类、性质测试都这样写，快。
- 后台线程：`helpers/import-files.js` 的 `makeFakeWorker(www目录, opts)` 给一个假的 Worker 类，在 Node 的 vm 里跑真的 `worker.js`。
  消息用 `structuredClone` 传，transfer 的 ArrayBuffer 真会被交走；`opts.failLoad(文件名)` 模拟线程脚本没加载上；`FakeWorker.created` 是起过的所有线程。
  在页面里用：`beforeParse` 里 `w.Worker=makeFakeWorker(...)`；不装就是「这台手机没有 Worker」，走主线程兜底。
- 加载整个页面又要用到 `import/` 下的脚本：JSDOM 选项加 `resources:{ interceptors:[ interceptor(www目录, 请求记录, { missing }) ] }`，
  `https://localhost/<路径>` 会映射到 `www/<路径>`（和安卓上一样）；请求记录用来断言「启动时没去加载」，`missing` 模拟某个文件缺了。
- jsdom 加载外部脚本要真的读文件，等结果时按时间等（见 `r-import-skeleton.test.js` 的 `until`），别只让几拍。
- 逐字节回归（`regress.js`）只比 `index.html` 启动后的输出，`import/` 下的文件不在里面。
- 测试用的虚构账单：`helpers/bills.js` 生成微信 / 支付宝的 CSV 和 xlsx（开头说明、表头照真实账单的结构，内容全是编的），能换编码、换列、改表头名、改头部统计、按行改字；`helpers/gbk.js` 把文字编码成 GBK（Node 只会解码 GBK）。GBK 里没有半角 ¥，GBK 账单里用全角 ￥。
- 导入的数据（单号表、待处理池、导入记录）用 `window.JiwenImportStore` 读写，测试里直接调它；库里的键是 `imp_<账号>_<存档号>_…`，`dumpDb` 能看到。
- 装回旧版本的测试：`s-import-data.test.js` 第 9 组用 1013-H 或之后的版本（`git show 9758ecf:www/index.html > /tmp/old.html`）；`p` 第 14 组、`q` 第 15 组是专门对 1013-F（整段存）写的，换成更新的版本跑会有几条不适用。

## 写新测试的约定

- 测试数据一律虚构，**不要放真实金额、真实备注或真实姓名**（仓库是公开的）。
- 用固定的「今天」（覆盖 `Date`），不要依赖运行测试时的真实日期。
- 数据按账号编号存（1010-K7 起）。测试照旧可以用老格式（`store_小明`）预置数据，启动时会自动迁移；当前账号编号是 `localStorage.getItem('app_logged_in_user')`。
- 账本在 IndexedDB（1013-D 起），启动、进入账号、新建账号、导入都是异步的：
  - `boot()` 是 async，用 `const t=await boot(...)`，返回时页面已经准备好；
  - 点账号、新建账号、导入之后 `await t.idle()` 再检查（等页面里进行中的读写都结束，见 `helpers/idb.js`）；
  - 读当前账号的账本：`JSON.parse(t.w.ledgerGet(t.w.storeKey()))`（内存里那份，合成一整本）；要确认真写进库了用 `(await t.db())['store_'+编号]`；
  - 1013-G 起库里是 `led_<编号>_m`（meta）和 `led_<编号>_<存档号>_<年-月>` / `…_none`（月份块）。`helpers/idb.js` 的 `dumpDb` 会额外合成一个
    `store_<编号>`，和 1013-F 整段存的一模一样，方便照旧断言；它不可枚举，`Object.keys(db)` 看到的仍是库里真实的键；
  - 测试里账本记录是「一改就报错」的（`helpers/idb.js` 打开了 `__LEDGER_STRICT`）：要改记录就换成新对象，`d[i]={...d[i], cat:'新'}`；
  - 模拟「重开 App」要用同一台手机：`boot` 时传同一个 IndexedDB（各文件里的 `reboot(t, 快照)`）。
- 每组结尾输出 `N 通过，M 失败`，并在有失败时 `process.exit(1)`，`run-all.js` 靠这个汇总；失败的条目（以「✗」开头的行）会在最后单独列出来。
- 不要比毫秒：机器忙的时候会偶发不过。要核对快慢，就数处理了多少数据（JSON 解析 / 序列化的字符数、解码 / 解压的字节数、查询看了几条），耗时只打印。
